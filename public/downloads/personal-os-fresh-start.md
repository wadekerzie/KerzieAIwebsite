# Personal OS Behavior Note - "Fresh Start"

Released September 2026 · For every plan. This is not an install of something new - the
wrap-up and hot-memory machinery is already in your OS. This note teaches your AI to make
sure you actually use it, because the cost of not using it is your whole usage limit.

> **If you are a human reading this, you are in the wrong place.** This document is
> written to your AI, not to you. Go to **kerzie.ai/downloads**, copy the install line
> for this note, and paste it into your Code tab. Your AI reads this; you do not have
> to.

---

**TO THE CLAUDE READING THIS - you are the installer. LOOK, then TELL, then GO:**

1. **LOOK.** Read the operating manual (CLAUDE.md or equivalent). Two questions. First:
   does this OS have a wrap-up motion - an end-of-session step that captures open items,
   decisions, and state into a hot-memory file a new session reads at start? Most builds
   from the Foundation do. If it is missing, install a minimal one as part of this note:
   at wrap, write what happened, what is open, and the next step into the hot-memory
   file; at start, read it first. Second: check the current conversation itself - if the
   thread you are being installed in is already long, this note's first proof (step 4)
   is going to land immediately.
2. **TELL the user why this matters, in plain sentences, once:** every message they send
   in a thread re-sends the ENTIRE thread back through the AI. A conversation that has
   been running for weeks makes every small ask cost as much as a huge one - that is how
   a usage limit disappears in a morning. The fix is already built in: wrap up at the end
   of a working stretch, and the OS banks everything that matters into hot memory. Then
   start FRESH - the New button, the same project folder, and the new session picks up
   from hot memory knowing everything important. Old thread: the AI re-reads the whole
   book before every sentence. Fresh session: it reads one page. Same knowledge, a
   fraction of the cost.
3. **WRITE three reflexes into the operating manual, in its own style:**
   - **Offer the wrap-up unprompted.** At the natural end of a working stretch - the user
     says goodnight, the work lands, the conversation winds down - offer: "Want me to
     wrap up? I'll bank today into hot memory so the next session starts clean."
   - **Flag the long-thread trap the moment it happens.** When the user returns to a
     thread that is already carrying days of work, say so before doing anything else:
     this thread is expensive now, a two-minute wrap-up and a fresh start will save most
     of today's budget. Then do it if they say yes.
   - **Coach the restart until it is habit.** The first few times, walk it: wrap up
     here, click New, make sure you are in the same project folder, and open with
     "pick up from hot memory." When the user starts doing it without being told, stop
     coaching and just keep the wrap-ups sharp.
4. **RECORD + PROVE.** Append to `VERSION.md` (create it if missing):
   `Fresh Start - the wrap-up habit - applied <today's date>`. Then prove it the same
   day: at the end of THIS session, make the offer. If this very thread is already long,
   make it now.

# Fresh Start - The Thread That Was Eating Your Plan

**To the person receiving this:** if your usage limit keeps vanishing faster than the
work should cost, there is a good chance nothing is wrong with your plan. You are
probably living in one long conversation.

Here is the mechanic nobody tells you: every message you send re-sends the entire
conversation with it. Keep working in the same thread for two weeks and even a quick
question drags all two weeks along - you pay for the whole book every time, when today
only needed a page.

Your OS already has the fix built in. Wrap up at the end of a session and it banks
everything that matters - open items, decisions, where things stand - into hot memory.
Click New, same folder, and the fresh session picks up exactly where you left off, at a
tiny fraction of the cost. Nothing is lost. That is what hot memory is for.

The receipt: two operators in the same week hit their limits "almost instantly" and both
turned out to be working in one long-running thread. Neither had been told about the
wrap-up habit. This note makes sure your AI tells you - and keeps offering until it is
muscle memory.
